# SlopKeeper Audit — 2026-11-23

Audited at v0.2.4 (commit cf65b3c). Method: full read of all 21 source modules,
live end-to-end runs (doctor → inventory → clusters → refs → plan validate/render →
apply --execute → scaffold → undo), targeted adversarial probes (symlinks, dotted
directory names, unicode paths, unreadable files, fifos, fingerprint drift, journal
collisions), and a 5,000-file scale test. Baseline is healthy: 625 tests pass,
ruff clean, REUSE compliant, sub-second commands on a 5k-file corpus.

Three findings are headline material because each contradicts a documented
guarantee, and all three were reproduced by running the tool:

1. The fingerprint drift gate is opt-in, not enforced. A plan that omits
   `based_on` applies cleanly against a corpus mutated after planning.
2. Moves escape the corpus root through symlinked directories. `safe_relpath`
   only symlink-checks the final path component.
3. Reference-integrity auto-rewrite silently skips citations whose path
   contains a dotted directory name (`my.files/report.md` reads as a hostname).

Everything else below is graded the same way: confirmed-by-execution first,
code-review findings second, and a roadmap for the three evolution goals —
robustness, complex corpora, agent ergonomics — plus what "code-refactor tool"
would actually require.

---

## What is genuinely solid

Worth naming explicitly, because the roadmap below must not erode it:

- The contract is excellent. Uniform JSON envelope with `ok` / `error.code` /
  `error.recovery`, `next` command chaining on success, exit codes 0/1/2, and
  an error-code table in AGENT_GUIDE.md enforced by a test
  (tests/test_error_codes.py). Every error encountered during this audit
  carried an actionable recovery string.
- The fingerprint is content-based and genuinely hard to fool: same-size,
  same-mtime content edits were detected (verified by stat-spoofing test).
  The `fp5:` prefix versioning the walk contract is a nice touch.
- All-or-nothing apply with a journaled, undoable move loop, dry-run default,
  human gate as rendered markdown, and idempotent scaffold (never overwrites;
  `*.slopkeeper-suggested` siblings) all work as advertised on the happy path.
- Chained-move rewrites resolve to final destinations (a→b→c cites land on c),
  and the rewrite pass edits citations in code comments as well as prose.
- Graceful degradation on hostile inputs actually held up: unreadable file
  (chmod 000) inventoryed with `title: null` instead of crashing; fifo skipped
  and reported by doctor as `non_regular_files`; newline-in-filename round-trips
  through JSON, the journal, and undo cleanly.
- Performance at 5k files: inventory 0.35s, doctor 0.7s, refs 0.3-0.4s. No
  blowups, though see the per-command re-walk waste in Robustness R6.

## Bugs and issues

### A. Confirmed by execution

**A1. Fingerprint gate bypass when `based_on` is absent (high).**
`apply.py:772-782` runs the staleness check only `if recorded`, where recorded
reads `plan.based_on.corpus_fingerprint`. A plan with no `based_on` key skips
the gate entirely — no `--force` needed. Verified: mutated a file after authoring
the plan, applied without `based_on`, the mutated file moved silently
(`ok: true, moved: 2`). Worse, `plan render` back-fills a *fresh* fingerprint
into such a plan (`cli.py:799-806`), so the human gate self-certifies a plan
that has no real binding to the corpus. The README's claim that "the silent
drift failure mode is closed" only holds for plans that carry `based_on` —
and it is the LLM-authored plan that is most likely to omit it.
Fix: make `based_on.corpus_fingerprint` a required field in `validate_plan`
(new error `plan_no_based_on`), bump the schema tag, and have render warn —
never fabricate — when it is missing.

**A2. Moves escape the corpus through symlinked directories (high).**
`models.py:105-153` (`safe_relpath`) checks symlink-escape for the final path
component only. A destination whose *intermediate* component is a symlink to
outside the root passes validation and is followed at execute. Verified: with
`corpus/notes -> /tmp/opencode/outside`, `apply --execute` moved `a.txt` out of
the corpus and into the symlink target; `plan validate` returned `valid: true`.
(`..` escapes are correctly refused with `path_escape`, so the textual check is
fine — it is the filesystem check that is partial.)
Fix: at apply time, immediately before each move, resolve the destination's
real parent and assert `root.resolve()` containment (`Path.is_relative_to`);
reject `..`-free plans whose resolved destination leaves the root. Decide
symlink policy explicitly — recommended: refuse to move *through* or *into*
symlinked dirs by default, with `--allow-symlinks` for deliberate cases.
Related: the corpus walk never follows symlinked dirs (inventory saw `dirs: 0`
for a symlinked dir), so symlinked content is invisible to inventory and the
fingerprint — an inconsistency between what coverage validates and what the
fingerprint covers.

**A3. Dotted directory names silently kill citation rewrites (high for agent
trust).**
`references.py:197-216` (`_urlish`) classifies any path token whose first
segment contains a dot with an alphabetic tail as a hostname and drops it.
Verified by controlled comparison: a stay-put file citing `myfiles/report.md`
gets `would_rewrite` at apply; the identical corpus with the dir renamed
`my.files` gets `would_rewrite: []` and no `reference_risks` either — after
`--execute` the citation points at a path that no longer exists. Corpus dirs
named `data.backup/`, `v1.0/`, `my.files/` are common. The basename fallback
keeps `refs` lookups mostly working, so this is invisible except through the
rewrite pass — precisely where silent breakage is worst, because the tool's
selling point is reference integrity.
Fix: only reject `://`-prefixed tokens or tokens whose first segment matches a
heuristic host pattern (2+ labels, last label 2-6 alpha, first segment has no
corpus dir match); always attempt corpus-path resolution first — if
`my.files/report.md` resolves to a corpus file, it is a path, not a URL.

**A4. Journal collision: two tends in the same second merge into one journal
(medium).**
`apply.py:64-66` names journals `journal-<UTC-seconds>.jsonl` and opens with
`"a"`. Verified: two consecutive `apply --execute` runs produced one journal
file; `undo` of that journal reverts *both* tends at once. The "undo one tend"
mental model from AGENT_GUIDE is wrong at second granularity.
Fix: append a counter (`journal-<ts>-2.jsonl`) if the path exists, and record
the tend id in the provenance header.

**A5. `refs` on a nonexistent basename reports "no citations" (medium, agent
trap).**
Verified: `refs <root> file_that_does_not_exist.md` returns `ok: true,
citation_count: 0`. Same payload as "exists, nobody cites it". Also verified:
when two corpus files share a basename (ambiguous), `refs note.md` returns
`citation_count: 0` with no `ambiguous_basenames` signal in the payload —
the agent must not distinguish "safe to move" from "you typoed" from "ambiguous,
tool refused to guess".
Fix: add `"exists": bool` and `"ambiguous": bool` fields to the refs payload
(the data already exists in `CitationIndex`; it just is not surfaced).

**A6. `.slopkeeperignore` `**` violates gitignore semantics (medium).**
`ignore.py:51-54`: a `**` segment requires at least one intervening directory,
so `a/**/b.md` does not match `a/b.md`. Verified directly against
`CorpusIgnore.is_ignored`. Gitignore says it should. Both humans and agents
will write rules believing gitignore semantics; a missed ignore means
SlopKeeper plans to organize files the owner meant excluded.
Fix: compile `a/**/b` to also match the zero-directory case.

**A7. Scaffold leaves literal `<Kind>` and duplicates the kind line (low,
cosmetic but visible).**
`scaffold.py:123-129` substitutes `<Role name>`/`<Name>`/`<Topic>`/`<Project>`
but never `<Kind>`; the by-kind strategy's skeleton (`by-kind.json:20`) opens
with `# <Kind>`. Verified: a scaffolded `docs/AGENTS.md` under by-kind renders
as `# <Kind>` with no folder name anywhere. Separately, every scaffolded
folder AGENTS.md carries a duplicated kind: `## Kind` section at top plus a
trailing `**Kind:** case` line (verified live; also baked into
tests/golden/scaffold_AGENTS.md, so the golden pins the bug in place).
Fix: add `<Kind>` to replacements; drop the trailing `**Kind:**` append;
regenerate goldens.

**A8. `plan validate` does not catch destination collisions against existing
files (low/medium).**
Verified: a plan moving `incoming.md` onto an existing `reports/incoming.md`
validates `valid: true`; only `apply` refuses (`dst_exists`). The README lists
"collisions" among validate's hard checks. The refusal is correct and
all-or-nothing, so this is a wasted agent round-trip rather than corruption.
Fix: run the same destination pre-flight in validate (it already stats the
corpus).

### B. Found in code review (high confidence, not each executed)

**B1. Undo ignores the journaled content hashes (medium).**
`apply.py` journals `{src, dst, sha256}` per move and `sha256_before` per edit,
and the module docstring (line 11) promises hashes as an integrity feature —
but `_undo_journal` (1259-1396) never compares them. A file modified after
being moved is "restored" as whatever it now contains. Fix: on undo, hash the
file at dst; mismatch → restore but report `content_changed` (or refuse
without `--force`).

**B2. One corrupt journal line makes the whole journal un-undoable (medium).**
`apply.py:1262-1267`: `json.loads(line)` sits inside a `try` that catches
`OSError` only; a torn final line (crash mid-write) raises `JSONDecodeError`
and `_undo_journal` dies. The journal is the last-resort recovery mechanism;
it should be maximally forgiving: skip-and-report malformed lines (the
provenance header already tolerates unknown ops).

**B3. Edits execute without write-time verification (medium).**
`apply.py:1115-1151`: `text.replace(find, replace, 1)` runs with no check that
`find` still occurs at write time. The exactly-once rule is validated against
*pre-move* content (`plan.py:884-890`); mid-run drift (external writer, or the
rewrite pass having touched a neighbor line) means the wrong occurrence — or
zero — can be replaced, and the edit is journaled as applied regardless. The
rewrite pass right above it does re-verify (`rep["old"] in lines[idx]`,
1074-1078); edits should match that discipline.

**B4. Destination-overwrite race between pre-flight and move (medium).**
`apply.py:794-807` pre-flights every destination; the move loop at 1003+ does
not re-check before `shutil.move` (1025) — a file created externally in the
window is silently clobbered (POSIX rename semantics). Same-fs fix that needs
no new deps: `os.link(src, dst)` (fails `EEXIST`, atomic no-replace) then
`os.unlink(src)`, falling back to `shutil.move` only across devices.

**B5. TOCTOU chains are accepted-by-design but undocumented (medium).**
One `apply --execute` observes the disk roughly six times (validate, fingerprint
gate, dst pre-flight, hash-then-move per file, rewrite re-reads, manifest), each
a separate snapshot; the tend lock is advisory and excludes only other
slopkeeper processes. `inventory` collects the file list and then
`corpus_fingerprint` re-walks (`inventory.py:217-290`) — the plan is authored
against two instants presented as one. This is tolerable given A1+A2 get fixed
(the fingerprint gate is the real defense), but the journal should record the
pre-move fingerprint and the executed fingerprint so drift is at least
forensic after the fact.

**B6. Files that fail `stat` are silently skipped by the fingerprint
(medium).** `models.py:229-231`: a file appearing/vanishing mid-walk, or being
temporarily unreadable, shifts the fingerprint nondeterministically instead of
erroring. Also: paths are digested with `encode(errors="replace")` (233), so
exotic filenames can collide into identical bytes; and files over the 64 MiB
cap contribute `mtime_ns`, contradicting the docstring's "a bare touch does not
move it" claim for exactly those files.

**B7. `tend_lock` is a silent no-op without `fcntl` (low/medium).**
`models.py:288-294` fail-softs on platforms without flock — Windows gets zero
serialization with no signal in any envelope. At minimum emit
`"warning": "no_locking_available"` in the apply payload.

**B8. Vector cache thrash between `draft --min-sim` and `clusters` (low).**
`similar.py:446` keys the cache params on `t1`; `draft --min-sim X` writes
`t1=X` to the same `vectors.json` that `clusters` always writes with
`t1=DEFAULT_T1` — alternating the two commands full-misses the cache every
time. tf payloads are t1-independent; key the cache on content hashes only.

**B9. `stale_version_pairs` ranks by mtime (low).** `similar.py:322-355`:
meaningless after rsync/git checkout/touch, which reset mtimes wholesale.
Consider filename-version signals (`v2`, `final`, `-copy`) as corroboration.

**B10. Strategy packs are not user-extensible (medium for the "complex
corpora" goal).** `strategies.py:18` reads only the packaged dir; adding a
rubric means editing the installed package. Support
`$XDG_CONFIG_HOME/slopkeeper/strategies/*.json` and `<root>/.slopkeeper/strategies/`
(override-by-id), and validate pack shape at load (a missing `folder_template`
currently explodes later in `scaffold.py:64` as a raw `KeyError` → the
`internal` envelope).

**B11. `scaffold` STATE.md gating ignores the strategy (low).**
`scaffold.py:75` reads `state_md` from the plan folder entry, never the
strategy's `folder_template.state_md`; `role-bots`/`projects` ship
`state_md: true` that does nothing on its own. Undocumented coupling an agent
can't be expected to know.

**B12. REPL gate is weaker than the CLI gate (medium for the human-gate
promise).** `tui.py:573` `/render` uses `build_ref_report`, not
`build_gate_report`: no rewrite summary, no straggler rows, no anchor risks.
`/refs` lacks `--dangling` and `--scan-path`; `/apply` lacks `--force` and
`--strict-references`. The docstring claims "the SAME commands" (`tui.py:7-9`).
The human gate is the safety story; it should show what the CLI shows.

**B13. Docs/claims drift (low, but agents read these files as ground truth).**
- `README.md:67` shows `slopkeeper plan render plan.json`; the parser requires
  both plan and root (verified: argparse usage error, exit 2).
- `README.md:124-125` and `AGENT_GUIDE.md:161-162` list four strategies; five
  ship (`by-kind` is real and used by `propose`).
- `README.md:202-204` claims design docs under docs/ (DESIGN.md, GARDEN.md,
  TEST_PLAN.md) and a site under docs/site/ — docs/ does not exist. `make docs`
  and `make docs-serve` are broken targets, and many code comments cite
  "DESIGN §x.y" against a file nobody can read.
- `README.md:88-127` omits the implemented `move`, `propose`, and `skill`
  subcommands from the command list.

### C. Test-coverage gaps

- Symlinks: zero tests create a symlink anywhere. A1/A2-class bugs could not
  have been caught. Add fixtures: symlinked dir mid-path (must refuse),
  symlink-as-leaf, symlink pointing at corpus root, hardlinked pair.
- Non-ASCII paths: no test puts a non-ASCII character in a *filename*; and
  Unicode NFC/NFD normalization (the macOS decomposed-name corpus) is untested
  and unhandled — `refs` basename matching does not casefold accents, and the
  fingerprint treats `é` (NFC) and `e\u0301` (NFD) as unrelated files, which is
  byte-correct but agent-surprising.
- True two-process races: flock is tested single-process only; add a subprocess
  race for concurrent apply and for concurrent `roots add` (roots.json writes
  are unlocked — `roots.py:71-78`).
- Journal corruption: no test for a torn/unparseable journal line (see B2) or
  for undo after post-move content mutation (see B1).
- The chmod-based writability test (`test_apply.py:2166`) is vacuous when the
  suite runs as root.
- Scale: caps are boundary-tested but no realistic multi-thousand-file run;
  the reference-scan bench is excluded from CI. A nightly 5k-file smoke would
  have caught the `similarity_cap` cliff's UX problem (below).

## Complex-corpus roadmap

The 3,000-file wall is the main cliff: `clusters` and `draft` hard-refuse past
it (`similar.py:39`, verified — a 5k-file corpus gets `similarity_cap`), and
the only documented answer is "partition per-directory". What complex corpora
actually need:

- **Blocking, not capping.** An inverted token→docs index (stdlib dict) gives
  candidate pairs that share a rare token; cosine on candidates only. This
  turns the O(n²) matcher into something that comfortably handles 50k files and
  raises MAX_FILES to a memory bound rather than a correctness cliff. Long-term:
  MinHash/LSH bands, still dependency-free.
- **Chunked planning.** `plan render` expands every rule move (the guide itself
  cites a 61k-entry case); add `plan render --summary-only` + `--out`, and let a
  plan scope to a subdirectory (`"scope": "inbox"`), with coverage enforced
  within scope while sibling scopes stay untouched. This makes "organize 50k
  files" a queue of bounded tends instead of one plan.
- **Hierarchical folder-bots.** The AGENTS.md layer is top-level-fold-centric
  (status folder-health only checks top-level dirs). Teach roster + status to
  recurse one more level, with root AGENTS.md linking child AGENTS.md — the
  navigation structure agents need in deep corpora.
- **Dedup as a first-class action.** `identical_groups` is a hint with no
  follow-through; add `apply`'s missing sibling operation: journal the loser
  into `archive/duplicates/<path>` (undo-safe, never delete). Fix
  `identical_groups`'s separate, narrower binary-skip list (`similar.py:289-299`
  hashes `.webp`/`.tar`/`.mp3`/`.db` files inventory already knows are binary)
  and the first-1MiB-blind "identical".
- **Cross-dir subtree copies.** `identical_subtrees` only compares flat children
  per parent dir; a copied tree one level deeper is invisible. Use recursive
  path:hash signatures.
- **Case-insensitive volume safety.** validate compares src/dst as exact strings;
  on a mounted case-insensitive volume `A.md→x.md` + `a.md→y.md` validates and
  clobbers. Add a casefold collision check (`plan_dst_case_collision`).
- **propose for all strategies** (role-bots, topics candidates are absent —
  the layout comparison silently narrows to three), plus per-candidate
  "files this layout would orphan unresolved" so the fork is legible.

## Agent-ergonomics roadmap

The JSON protocol and `next` chaining are already agent-first. The gaps that
showed up in real runs:

- Honest query payloads (A5): `exists`/`ambiguous` on refs; a `warnings[]`
  array on envelopes for the soft problems (no locking, truncated 512 KiB
  citation scans — currently a citation beyond the cap in one file is dropped
  in total silence, unlike inventory's loud `truncated`).
- Machine-readable recovery on errors: `error.recovery` is prose; add
  `error.suggested_command` mirroring the success-path `next`, so agents can
  auto-recover without regexing sentences.
- REPL/CLI gate parity (B12) — humans deserve the full gate; agents driving
  `plan render` already get it.
- Stable file handles: post-apply, every path an agent cached is stale. Return
  a `path_map` (old→new) in the apply payload (it is already in `moved`) plus
  in scaffold/undo envelopes as a canonical field; consider content-hash file
  ids for long-lived agent sessions.
- User-extensible strategies (B10) — custom rubrics are the intended way to
  encode a household's conventions without a release.
- NFC/NFD normalize-on-match in `CitationIndex` (cheap: casefold + NFD both
  sides) — mixed-Mac corpora are otherwise citation-invisible.
- Docs (B13): agents treat README/AGENT_GUIDE as truth; fix the render example,
  the strategy list, and either commit the missing DESIGN.md or purge the
  references (the Makefile docs targets are dead weight either way).

## More filetypes, and the code-refactor question

**Filetypes (incremental, low-risk):**

- OOXML siblings of the existing pptx trick: `.odt`/`.ods` (unzip
  `content.xml`, strip tags), `.epub` (zip, read `container.xml` → title).
  `.doc`/`.xls` via optional external binaries, following the existing
  pdftotext/pandoc EXTRACTORS pattern (`inventory.py:85-92`) — absent tool →
  NO_SIGNAL marker, never silence. That pattern is good; extend it.
- Suffix-less classics via a name table: Makefile, Dockerfile, Justfile,
  Gemfile, .env, .gitignore, LICENSE — currently invisible to the references
  scan (`is_text_file` is extension-gated, `references.py:94-95`) even though
  they constantly cite filenames.
- Content-sniffing fallback in `is_text_file` (reuse inventory's NUL sniff):
  `.dart`, `.vue`, `.ex`, `.tf`, `.proto`, `.gradle` etc. are currently
  unscannable for references while inventory happily calls them text. This
  also lets the CODE_EXTS list stop being a maintenance treadmill — extension
  table as fast path, sniff as truth.
- `.ipynb`: title is currently `{` (`inventory.py:171-185` — first line of
  JSON). Parse the first markdown cell instead (stdlib json; the extension is
  already in TEXT_EXTS so it also needs cell-aware tokenization in `similar`).
- Code-aware similarity: `_doc_tokens` weights stem×8/title×3/head×1, and for
  code the head is 400 chars of license header or imports. For code files,
  tokenize def/class/function signatures from the whole file (regex is enough
  for a hint tool) and add code stopwords (`def`, `return`, `import`, `self`)
  to STOPWORDS — today's list suppresses prose words only.

**Code refactor: what's here, what's missing.** The bones are surprisingly
close: journal + undo + fingerprint gating + human gate are exactly what a
rename tool needs, `anchors.py` already understands `os.path.join(base, "data")`
string literals and `__file__` math, `refs` already rewrites citations inside
.py comments, and doctor already detects git repos/node_modules/nested repos.
What keeps it out of "refactor tool" territory today:

1. **No module graph.** `import a.b.c` / `from x import y` / `require("./x")`
   are not citations (`references.py` only matches path-shaped tokens). Phase
   one is *detection as a new citation kind* (`kind: "import"`, resolved via
   sys.path-adjacent heuristics for python, relative specifiers for JS/TS,
   import paths for Go) — report-only in `refs`, risk-flagged in validate,
   no rewrites. That alone makes "move a package" safe enough to attempt.
2. **No language-safe editing.** The rewrite engine is line-text `replace`;
   editing code strings/comments/identifiers alike needs per-language
   string/comment awareness. Stdlib `tokenize` gives a real one for Python
   (free win: never rewrite inside a non-path string); regex comment/string
   maskers get 80% for JS/TS/Go/Rust. Keep it a gate flag: `rewrites.code:
   "mask" | "off" | "force"`.
3. **No verification loop — the killer feature.** Folders already carry `kind`
   and `role`; add `verify_command` (e.g. `pytest -q`, `npm test`, `tsc
   --noEmit`). `apply --execute --verify` runs the corpus's check after
   moves/rewrites and auto-`undo`s on failure. The journal makes this
   practical today, and the all-or-nothing story finally covers semantics,
   not just topology. This is the one feature that would make SlopKeeper
   genuinely differentiated as a code mover.
4. **No git cooperation.** For `git_repo: true` corpora: prefer `git mv` (rename
   tracking), refuse dirty-tree moves without `--force` (fingerprint sees
   content drift but not staged-state drift), record HEAD in the journal
   provenance header, and offer `git checkout -- .` as an escape hatch in undo
   guidance. Keep git optional — `git` absent changes nothing.
5. **Anchors should graduate from flag to proposal.** `anchors.py` already finds
   string-literal corpus paths but only prices risk; emit them as suggested
   plan `edits` (agents approve them at the human gate — the pattern already
   exists via `edits` + exactly-once validation).

Scope guard for all of the above: keep core stdlib-only. Semantic-heavy pieces
(AST rewrites) belong either in an optional extra (`slopkeeper[code]` pulling
tree-sitter) behind a feature probe, or — better aligned with the project's
own philosophy — stay in the *agent's* lap: SlopKeeper detects and reports the
import graph as JSON; the agent authors the `edits`; the gate + journal +
verify loop make it safe. "Agent decides, tool guarantees" is the moat;
don't trade it for a half-built codemod.

## Suggested sequencing

1. A1, A2, A3 — the three contract-breaking bugs, each with regression tests
   (symlink fixtures finally). ~1 week, restores the README's claims.
2. A4-A6, B1-B4 — journal and execute-time hardening. ~1 week.
3. R6/R7 — single-pass scanner + unified kinds (perf and consistency in one
   refactor; touches every module, do before feature work).
4. Complex-corpus: inverted-index blocking + chunked scoping (unlocks the
   3k-60k tier, which is where "complex" actually lives).
5. Filetype batch (OOXML/odf/epub/sniff-fallback/name-table) — low risk,
   mostly `inventory.py` + `references.py`.
6. Code track: import-citation detection → verify_command + auto-undo →
   git cooperation. Each is independently shippable behind the existing gate.
